# Next.js over vanilla HTML/CSS/JS or Astro

Status: accepted

For a simple static portfolio, vanilla HTML/CSS/JS was the technically leanest option and Astro the best content-site fit — both were recommended during planning. We chose **Next.js** anyway because the owner values the wide ecosystem of ready-made components (shadcn/ui and similar) and wants React/Next experience to carry over into other work. The extra build complexity is accepted as a deliberate trade-off for ecosystem leverage.

## Considered Options

- **Vanilla HTML/CSS/JS** — zero dependencies, but no component reuse; rejected as too limiting for future growth
- **Astro** — ideal for content-heavy sites, but the owner cut all blogging ambitions, removing Astro's main advantage
- **Next.js** — chosen: component ecosystem + transferable skills outweigh the overhead for a ~3-page static site
